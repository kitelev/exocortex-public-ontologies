Understanding SKOS

12 min read • Intermediate • Vocabulary

SKOS (Simple Knowledge Organization System) is a W3C standard for representing thesauri, taxonomies, classification schemes, and other structured vocabularies in RDF.

When to Use SKOS

Use SKOS Use OWL
Organizing content by topics Defining formal ontologies
Migrating existing thesauri Complex reasoning requirements
Subject headings for libraries Domain modeling with constraints
Tag/category systems Data validation
Fuzzy, overlapping concepts Strict class hierarchies
SKOS vs OWL Classes

SKOS concepts are not OWL classes. A skos:Concept represents a unit of thought, while an owl:Class represents a set of individuals. Use SKOS when you're organizing knowledge for humans; use OWL when you need machine reasoning.

Core Components

Concepts and Concept Schemes

@prefix skos: <http://www.w3.org/2004/02/skos/core#> .

# A concept scheme is a container for concepts
:subjects a skos:ConceptScheme ;
    skos:prefLabel "Library Subject Headings"@en ;
    skos:hasTopConcept :science, :humanities, :arts .

# Individual concepts
:science a skos:Concept ;
    skos:prefLabel "Science"@en ;
    skos:inScheme :subjects ;
    skos:topConceptOf :subjects .

Hierarchical Relationships

  • Science (top concept)
    • Natural Sciences
      • Physics
      • Chemistry
      • Biology
    • Computer Science
:naturalSciences a skos:Concept ;
    skos:prefLabel "Natural Sciences"@en ;
    skos:broader :science ;
    skos:narrower :physics, :chemistry, :biology .

:physics a skos:Concept ;
    skos:prefLabel "Physics"@en ;
    skos:broader :naturalSciences .

:chemistry a skos:Concept ;
    skos:prefLabel "Chemistry"@en ;
    skos:broader :naturalSciences .

:biology a skos:Concept ;
    skos:prefLabel "Biology"@en ;
    skos:broader :naturalSciences .

Labels and Documentation

Property Purpose Cardinality
skos:prefLabel Preferred/canonical name One per language
skos:altLabel Synonyms, abbreviations Any number
skos:hiddenLabel Search terms (not displayed) Any number
skos:definition Formal definition Any number
skos:scopeNote Usage guidance Any number
skos:example Examples Any number
skos:notation Codes (e.g., DDC numbers) Any number 
:artificialIntelligence a skos:Concept ;
    skos:prefLabel "Artificial Intelligence"@en ;
    skos:prefLabel "Intelligence artificielle"@fr ;
    skos:altLabel "AI"@en ;
    skos:altLabel "Machine Intelligence"@en ;
    skos:hiddenLabel "artifical inteligence"@en ;  # Common misspelling
    skos:definition "The simulation of human intelligence by machines."@en ;
    skos:scopeNote "Use for general AI topics. For specific techniques, use narrower concepts."@en ;
    skos:notation "006.3" .  # Dewey Decimal

Associative Relationships

Use skos:related for concepts that are associated but not hierarchically:

:climateChange a skos:Concept ;
    skos:prefLabel "Climate Change"@en ;
    skos:related :renewableEnergy ;
    skos:related :carbonEmissions ;
    skos:related :environmentalPolicy .

:renewableEnergy a skos:Concept ;
    skos:prefLabel "Renewable Energy"@en ;
    skos:related :climateChange .  # Symmetric by convention

Mapping Between Vocabularies

SKOS provides properties to link concepts across different vocabularies:

Property Meaning
skos:exactMatch Concepts are equivalent (transitive)
skos:closeMatch Concepts are similar enough to be interchangeable in some contexts
skos:broadMatch Target concept is broader
skos:narrowMatch Target concept is narrower
skos:relatedMatch Concepts are related (cross-scheme) 
@prefix lcsh: <http://id.loc.gov/authorities/subjects/> .
@prefix dbr: <http://dbpedia.org/resource/> .

:artificialIntelligence
    skos:exactMatch lcsh:sh85008180 ;           # Library of Congress
    skos:closeMatch dbr:Artificial_intelligence . # DBpedia

Collections

Group concepts without creating a hierarchy:

# Unordered collection
:europeanCountries a skos:Collection ;
    skos:prefLabel "European Countries"@en ;
    skos:member :france, :germany, :spain, :italy .

# Ordered collection (numbered list)
:priorityLevels a skos:OrderedCollection ;
    skos:prefLabel "Priority Levels"@en ;
    skos:memberList ( :critical :high :medium :low ) .

Complete Example: Subject Vocabulary

@prefix skos: <http://www.w3.org/2004/02/skos/core#> .
@prefix dct: <http://purl.org/dc/terms/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

# The vocabulary itself
:techSubjects a skos:ConceptScheme ;
    skos:prefLabel "Technology Subject Headings"@en ;
    dct:creator "Example Organization" ;
    dct:created "2024-01-01"^^xsd:date ;
    skos:hasTopConcept :computing, :engineering .

# Top-level concept
:computing a skos:Concept ;
    skos:prefLabel "Computing"@en ;
    skos:prefLabel "Informatique"@fr ;
    skos:definition "The study and use of computers and computational systems."@en ;
    skos:inScheme :techSubjects ;
    skos:topConceptOf :techSubjects ;
    skos:narrower :softwareEngineering, :networking, :dataScience .

# Second-level concepts
:softwareEngineering a skos:Concept ;
    skos:prefLabel "Software Engineering"@en ;
    skos:altLabel "Software Development"@en ;
    skos:broader :computing ;
    skos:narrower :programming, :testing, :devops ;
    skos:related :projectManagement .

:programming a skos:Concept ;
    skos:prefLabel "Programming"@en ;
    skos:altLabel "Coding"@en ;
    skos:broader :softwareEngineering ;
    skos:narrower :webDevelopment, :mobileDevelopment, :systemsProgramming ;
    skos:scopeNote "Use for general programming topics. For specific languages, use narrower concepts or language-specific vocabularies."@en .

:webDevelopment a skos:Concept ;
    skos:prefLabel "Web Development"@en ;
    skos:broader :programming ;
    skos:related :networking ;
    skos:notation "WEB-DEV" .

# Cross-scheme mapping
:webDevelopment
    skos:exactMatch <http://id.loc.gov/authorities/subjects/sh2008003477> .

Best Practices

SKOS Integrity Constraints
  • One skos:prefLabel per language per concept
  • No concept can be skos:broader of itself (no cycles)
  • skos:related is symmetric; use consistently in both directions
  • skos:exactMatch is transitive; use carefully

Integration with Other Ontologies

  • Dublin Core — Use dct:subject to link resources to SKOS concepts
  • DCAT — Categorize datasets using SKOS vocabularies
  • Schema.org — schema:about can point to SKOS concepts
  • OWL — SKOS concepts can be instances of OWL classes
