What Are Ontologies?

An ontology is a formal description of knowledge within a domain. Think of it as a shared vocabulary that enables:

  • Common understanding — Everyone uses the same terms with the same meanings
  • Machine readability — Computers can process and reason about the data
  • Interoperability — Different systems can exchange data seamlessly
  • Reusability — Build on existing standards instead of reinventing the wheel

For example, instead of everyone defining "Person" differently, we can all use foaf:Person from the FOAF ontology, ensuring our data is compatible.

Why Use Public Ontologies?

🔗 Interoperability

Your data can be understood and integrated with other systems that use the same ontologies.

📊 Data Quality

Standardized vocabularies improve consistency and reduce ambiguity in your datasets.

🔍 Discoverability

Data described with standard ontologies is easier to find, query, and analyze.

⚡ Faster Development

Reuse proven models instead of designing from scratch. Focus on your domain.

Quick Start Guide

  1. Explore the ontologies
    Start with the interactive browser. Use the namespace graph to understand relationships between ontologies.
  2. Understand the structure
    Each ontology defines Classes (types of things), Properties (relationships), and Datatypes (value formats).
  3. Try SPARQL queries
    Use our SPARQL Playground to query the ontologies. Example: find all subclasses of foaf:Agent.
  4. Use in your project
    Reference ontology terms using their URIs. For example: 
    @prefix foaf: <http://xmlns.com/foaf/0.1/> .

:john a foaf:Person ;
    foaf:name "John Doe" ;
    foaf:knows :jane .
  5. Validate with SHACL
    Use SHACL shapes to validate that your data conforms to expected patterns.
